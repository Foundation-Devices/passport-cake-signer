# Cake Wallet Signer for Passport Prime

A Monero cold signer for [Foundation Passport Prime](https://foundation.xyz),
built as a native KeyOS app and designed to pair with the public
[Cake Wallet](https://cakewallet.com) mobile app.

Cake remains the online/watch-only wallet. Passport Prime holds the Monero spend
key offline, reviews unsigned transactions built by Cake, signs locally, and
returns Cake-compatible signed transactions over animated QR.

Current status: real hardware signing works. A transaction has been signed on
Passport Prime, scanned back into Cake Wallet, and sent successfully.

## System Model

Passport is the cold signer. Cake Wallet is the online watch-only wallet.

Cake gets:

- Primary Monero address
- Private view key
- Restore height
- Key images generated by Prime when Cake requests spent-output sync

Cake does not get:

- Private spend key
- Prime device seed
- Imported wallet seed phrases

The normal QR flow is:

```text
Passport Prime                         Cake Wallet mobile
--------------                         ------------------
Pairing QR --------------------------> Restore watch-only wallet

                                      Scan chain / track balance

                         <----------- xmr-output QR, if Cake needs spent-output sync
xmr-keyimage QR ---------------------> Import key images

                         <----------- xmr-txunsigned QR
Review and sign locally
xmr-txsigned QR ---------------------> Broadcast signed transaction
```

The app also still has file-export hooks for view-only data, key images, and
signed transactions, but the current demo path is QR-first.

## Interop Boundary

The app does not invent a new Monero transaction format.

Cake and Prime exchange standard Monero `wallet2` blobs:

- `unsigned_tx_set`
- `signed_tx_set`
- `output_export`
- `key_image_export`

The QR layer is CupCake-compatible UR transport. `src/qr.rs` wraps the raw
wallet2 blob as a CBOR bytestring and emits animated UR frames with Cake's
Monero UR types:

- `xmr-txunsigned`
- `xmr-txsigned`
- `xmr-output`
- `xmr-keyimage`

The cryptographic code is transport-agnostic: the same raw wallet2 data can be
handled by QR or file.

## Signing Flow

When Cake shows an unsigned transaction QR, Prime:

1. Reassembles the animated UR payload.
2. Unwraps the CBOR bytestring into the raw `unsigned_tx_set`.
3. Verifies the wallet2 authentication signature before decrypting.
4. Decrypts with the wallet private view key.
5. Parses transaction construction data, sources, destinations, fee/change, and
   account/subaddress metadata.
6. Shows the user a review screen.
7. Signs with the private spend key using the Rust Monero stack.
8. Packages the signed transaction as a wallet2 `signed_tx_set`.
9. Returns `xmr-txsigned` animated QR frames for Cake to scan and broadcast.

The signer currently builds a single Monero transaction using CLSAG and
Bulletproof+ via the `monero-wallet` / monero-oxide stack. The resulting signed
set is encrypted and authenticated in wallet2 format so Cake can import it.

## Key-Image Sync Flow

Cake watch-only wallets need key images to know which outputs are already spent.
When Cake requests sync, Prime:

1. Scans Cake's `xmr-output` animated QR.
2. Decrypts and parses Cake's wallet2 output export.
3. Computes each output's one-time secret.
4. Generates the Monero key image and a verifying signature.
5. Builds a wallet2 `key_image_export`.
6. Returns it as `xmr-keyimage` animated QR.

Prime caches output details per wallet during the app session. If Cake sends only
an incremental suffix and Prime does not have the missing prefix cached, Prime
asks the user to switch Cake to a full output export rather than returning a
malformed partial key-image set.

## Wallet Model

The app has a wallet book stored under the app's local data directory.

Wallet types:

- `DeviceSlot`: deterministic Prime-derived wallet.
- `ImportedPolyseed`: imported 16-word Polyseed wallet.
- `ImportedLegacy`: imported 24/25-word legacy Monero mnemonic wallet.

Slot 0 preserves the default app-seed derivation. Additional Prime-derived
wallets are domain-separated child slots of the KeyOS app seed, so they are
deterministic and recoverable from the device seed plus the same app logic.

Imported seeds are sealed locally:

- Encryption: XChaCha20-Poly1305
- Key: domain-separated hash of the KeyOS app seed
- AAD: wallet record ID
- Storage: `wallets.json`

The imported seed phrase is never exported automatically. It can be displayed
from the wallet's seed screen after the user opens that wallet.

## Address Verification

The address verification screen can:

- Scan a Cake Monero address QR.
- Detect obvious Bitcoin address QRs and show a targeted error.
- Search local wallets through common account/subaddress indexes.
- Derive a specific account/subaddress address on demand.

This helps users confirm that a Cake receive address belongs to a specific Prime
wallet before pairing or funding.

## Performance Notes

Monero is heavier than Bitcoin on embedded hardware.

The biggest unavoidable cost in this flow is wallet2's CryptoNight-derived
ChaCha file key. On Passport Prime this can take several seconds in software.
The app memoizes that key and warms it in a background thread when a wallet is
selected, which makes subsequent unsigned-tx parsing, key-image sync, and signing
much smoother.

Signing can still pause for a few seconds because RingCT proof/signature
generation is computationally heavy. Large QR payloads also take time to scan,
especially if the phone camera or Cake scanner misses frames.

## Build And Test

This app is SDK-shaped, but it builds inside a full KeyOS workspace because it
depends on workspace crates such as `slint-keyos-platform`.

Run app tests from the KeyOS workspace:

```bash
cargo test -p gui-app-cake-signer
```

Build and flash a signed device image from the KeyOS workspace:

```bash
cargo xtask build
cargo xtask build-firmware-image
cargo xtask flash --system --switch
```

Do not flash unsigned builds on production hardware.

## Known Limitations

- Multi-`pending_tx` wallet2 sets need more fixture coverage.
- Integrated-address/payment-ID destinations are currently rejected by the
  signer path.
- Large transactions may push QR scan time and signing time beyond what feels
  polished.
- The app needs broader regression fixtures from real Cake exports across:
  multiple recipients, many inputs, subaddresses, different fee conditions, and
  fresh vs previously synced watch-only wallets.
- USB/file handoff is present as a fallback, but QR is the primary tested path.

## FAQ

### Can Cake Wallet spend funds?

No. Cake receives the private view key, not the private spend key. Cake can scan,
track balances, and build unsigned transactions, but only Prime can sign.

### What does Prime actually sign?

Prime signs a Monero transaction built by Cake's watch-only wallet. The data is a
standard Monero wallet2 `unsigned_tx_set`, transported as a Cake/CupCake
animated QR.

### Is this compatible with the public Cake Wallet build?

Yes. The current demo path uses Cake/CupCake UR types and wallet2 data. A real
transaction has been signed on Passport Prime, scanned into Cake Wallet, and
sent.

### Why does Cake sometimes ask for a key-image sync before signing?

Monero wallets need key images to know which outputs are already spent. A
watch-only wallet cannot compute them by itself, so Cake asks Prime to compute
and return them.

### Does Prime expose the private view key?

Yes, intentionally, for watch-only pairing. The private view key lets Cake see
wallet activity for that wallet. It does not allow spending.

### Can users import existing Monero wallets?

Yes. The app supports 16-word Polyseed and 24/25-word legacy Monero mnemonics.
Seeds can be imported by Cake seed QR, typed text, or UTF-8 text file.

### Do Prime-derived wallets have their own seeds?

Yes. Each Prime-derived wallet slot has a deterministic 16-word Polyseed. Slot 0
is the default wallet; additional slots are deterministic children of the KeyOS
app seed.

### Are Cake accounts and subaddresses supported?

The app parses Cake transaction account/subaddress metadata and can derive or
verify Monero subaddresses locally. The Prime UI does not try to become a full
Monero wallet/account manager; Cake remains the wallet.

### What happens if the wrong Prime wallet is selected?

Prime first tries the selected wallet. If authentication/decryption fails, it
checks the other local wallet records. If another wallet matches, the app can
switch to it; otherwise it shows a wrong-wallet error.

### Why can signing feel slow?

Monero RingCT signing is computationally heavy, and wallet2 file encryption uses
CryptoNight-derived keys. The app caches and warms the CryptoNight key, but
proof/signature generation and animated QR transfer still take time.

### Does the app use SeedQR?

No. This app uses plain text seed QR import/display for Cake-compatible Monero
seed handling, not the Bitcoin SeedQR standard.

### Is this a KeyOS SDK-compliant app?

It follows the KeyOS app structure: manifest, `app!` macro, Slint UI, app-seed
permission, scanner/file APIs, and workspace build integration.
